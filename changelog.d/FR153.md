## Fixed

- `pyfs-matrix post` no longer skips every sampled velocity field of a run of FlightStream 26.124 on a build other than the one its velocity convention was measured on (FR-153 R1). A run of a measured solver version, export family and unit on another build, for example a cluster build run with `--accept-unregistered-build`, gets its fields written with the convention measured on build 8172026; one warning per point in `post.log` and in the console names both builds, and each field's `products.json` entry records `velocity_convention` with `measured_on_build`, `run_build` and `proven` false. Another solver version or unit is refused as before, and a run of the measured build is unchanged. The measured conventions are now one table, `VELOCITY_EVIDENCE` in `pyflightstream.post.field_frames`, so registering a build is one row; `docs/sampled-fields.md` says how the convention was measured and how to measure it on another build.
