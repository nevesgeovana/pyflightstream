## Added

- A new run status, `RAN_MISSING_LOG`: every output of a point is present and its declared solver log is absent (deleted after the run, or never copied back). `collect`, the grouped collect and `rebuild` decide it by one rule before anything waits for the log or reads the job's end files; the record's `residual_note` names what only the log carries (the residual history, the convergence verdict, the frozen-point reading, the solver clock and the iteration count), `wall_time_s` is null and the point is never `CONVERGED`. The post writes every product of such a point, with or without `--check-frozen`, and `post.log` carries one WARNING per point (FR-413).
- `pyfs-matrix rebuild` rebuilds grouped runs (`--batch`, `--polar-sweep`): a batch point's script is compared at its batch folder, the rebuilt record names its batch and its job (from the plan receipt), and a simulation still in its batch folder is rebuilt from there and left `SUBMITTED` for `collect` to move home and complete (FR-412).

- `pyfs-matrix mark-converged --sims ID [ID ...] [--points NAME ...] --reason TEXT [--apply]` records a person's verdict of `CONVERGED`, the twin of `mark-failed`: each record keeps under `marked` the status it had, the time, the reason and the verdict, and `runs.json` is archived first; a point SUBMITTED, without its loads export, deleted or marked failed is refused by name. `show`, `status --points`, `post.log` and every `products.json` entry built from a marked point name the verdict, and `rebuild` and `sync` keep it (FR-414). From Python: `pyflightstream.run.records.mark_converged`.

## Changed

- A bare matrix name or stem found in the workspace's root or `inputs/matrices/` is the matrix of every command, `rebuild` included: a same-named file in the working directory is no longer read and no longer refuses the command; when its bytes differ, a WARNING names both files and says the workspace's was read (FR-411).
- Every simulation `rebuild` refuses is named with its reason and what to do, the summary ends with the count rebuilt and the count refused, and `rebuild --apply` with nothing to write prints every refusal before it stops (FR-412).
- `status` counts `RAN_MISSING_LOG` among the runs that ended and apart from `CONVERGED`, and `run --resume` does not run such a point again (FR-413).

## Fixed

- `pyfs-matrix rebuild` no longer refuses every simulation of a matrix kept in `inputs/matrices/` that has a `RUN 0` row as being "in both homes of the workspace with different content": its throwaway copy held the matrix twice, once re-activated (FR-411).
- `pyfs-matrix rebuild` no longer refuses every grouped simulation as "the executed script is not the script pyflightstream renders": a batch point's script names its batch folder (FR-412).
- `collect` no longer waits forever for the log of a grouped point whose cumulative log was deleted, and no longer fails as FAILED_EXECUTION a point whose end-of-job files and outputs are present and whose log is not (FR-413).

## Migration

- A command run from a folder that holds a different file of the matrix's name now reads the workspace's matrix with a WARNING instead of stopping. To read the other file, name it with its folder, for example by its absolute path (FR-411).
- A reader of `runs.json` must accept the status `RAN_MISSING_LOG`. A point recorded with it is not a failure and its products are written; a script that counted only `CONVERGED` and `COMPLETED_MAX_ITER` as runs that ended should count it too (FR-413).
