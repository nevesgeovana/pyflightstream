## Added

- `pyfs-matrix plan` and `pyfs-matrix run` take `--sims SIM [SIM ...]` and `--points POINT [POINT ...]`: one simulation, or one simulation and some of its points by the point name the plan prints, is planned and run without editing the matrix. The matrix file is not written, every point not selected is not planned, staged or run and keeps its record, and an id or a point the matrix does not carry is refused before anything runs, naming it and the ones that exist. `plan_matrix` and `run_matrix` take the same selection as `sims` and `points` (FR-326).
- A second `pyfs-matrix run` of a matrix with recorded points, without `--resume`, is still refused with exit status 2 and runs nothing, and now prints the command that continues it: the command as it was invoked with `--resume` added, quoted for the shell it was typed in, and the count of recorded points and of points that would run. The library refusal stays a `WorkspaceError`, which now carries the counts as `recorded` and `would_run` (FR-327).

## Changed

- `pyfs-matrix run --sims` without `--force-rerun-all`, which 0.33.0 refused, now runs only those simulations; `--sims` with `--force-rerun-all` keeps its 0.33.0 meaning, and `--points` beside `--force-rerun-all` is refused. The refusal became a selection, so a script that relied on the refusal sees a run (FR-326, which amends FR-131).
- The command-line cheatsheet carries `--sims` and `--points` on the entries of `plan` and `run` (FR-326).

## Migration

- `pyfs-matrix run --sims 2031 2032` without `--force-rerun-all` was refused in 0.33.0 and runs those two simulations from 0.34.0. Add `--force-rerun-all` to redo recorded points, as before; use `plan --sims` to rehearse the same selection (FR-326).
