## Changed

- The `--batch` and `--polar-sweep` help of `plan` and `run` names every class of row the grouped modes leave out: RESTART rows, LEGACY rows and coupled rows on `steady` or `qsteady_rotor`, and says to run those rows point by point, without the flag (FR-421).
- The plan's left-out line of a coupled `steady` or `qsteady_rotor` row now names the remedy (run these rows point by point, without `--batch` or `--polar-sweep`) and no longer cites a report id; the exclusion itself is unchanged (FR-410, amended by FR-421). Every left-out reason the grouped plan prints comes from one table in the code, and none names a report id (FR-421).
- `scripts/check_parity.py` compares the left-out reasons of the grouped plan per matrix, mode and simulation, and names the one changed text of the coupled row under FR-421 (FR-421).
- The grouped-plan workspace fixture of the tests lives in `tests/support_helpers.py`, and the refusal comparison of `scripts/check_parity.py` is tested without `plan.json` and with it (NFR-42).

## Migration

- Scripts or notes that match the text "(RPT-150)" in the plan's left-out line of a coupled steady row must match the new wording; `plan.json` keeps the same `left_out` keys and only the reason string changed (FR-421).
