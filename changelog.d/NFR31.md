## Changed

- Reports state the solver build, and executable hashes are withheld (NFR-31). The committed reports, compatibility, physics and probe records and test fixtures identify the executable of every build in the identity baseline (25.000 to 26.124) by its build, and a digest field reads `withheld; build <build>`. The compatibility, physics and drift report writers, and the C01 instrument's committed receipt copies, now write that form for a recorded digest and never the digest itself; an unrecorded one still reads "not recorded". Reports name their files inside `<workspace>` or `<local probe folder>` instead of a machine path. The package's measured frame-timing and velocity conventions are keyed by version, build and unit, and still require the run to have recorded its own `fs_exe_sha256`, which the run record and the products keep. `read_executable_baseline` reads a withheld cell as a row with no public digest, so `classify_executable` compares a binary by its build through the identity-only probe; a local, uncommitted copy of the baseline that keeps the digests compares bytes as before. A tier-1 guard (P0330-NO-EXE-HASH) refuses a labelled executable digest of any build, a withheld digest anywhere and an absolute user path in any tracked text file.
