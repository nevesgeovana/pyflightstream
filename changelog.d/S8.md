## Added

- `[products] installed_frame` in the pproc, a list of families from `probes` and `inflow` (default empty; another family is refused when the pproc is read, naming the accepted ones): the post writes `probes/<point>_probes_installed.csv` beside each probes table and `fields/<stem>.inflow_installed.dat` beside each reusable inflow profile, each the table mirrored through `y = 0`, listed in `products.json` with kind `installed_frame` and its source table in `source`; a column the classification cannot place is copied unchanged and named once per simulation in `post.log` (FR-420).

## Changed

- The classification of the installed-frame copy (`FLIPPED_COLUMNS`, the one list `to_installed_frame` and the post read) also holds the `Y` position, the `VY` velocity and the x and z components of a vorticity (`VORTICITY_X`, `VORTICITY_Z`), and its roll pattern no longer matches `CREF` (FR-420).

## Migration

- `to_installed_frame` now negates the `Y`, `VY`, `VORTICITY_X` and `VORTICITY_Z` columns of a table that carries them, where it copied them unchanged, and no longer negates a `CREF` column, which the roll pattern `CR[A-Z]*` matched by mistake: a table carrying the reference chord had that column's sign reversed. Copies written by 0.36.0 from a table with either kind of column differ from the ones written now.
