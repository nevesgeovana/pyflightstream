## Added

- `pyflightstream._textio`, the one floor module every text file of the package is written through: `write_text`, `open_text`, `append_text`, `write_lines`, `write_json`, `write_csv` and the CSV writers all end a line with LF on every platform. A tier-1 guard walks `src/` and refuses a text write outside it, with ten planted bypasses as its control (NFR-32).
- `scripts/lf_products_check.py` posts the recorded offline campaigns on the platform it runs on and writes the receipt of the LF arm: files checked, emitted scripts checked, files holding a CR byte, and the guard's control (NFR-32).
- RPT-140, the census of the text writers that gave CRLF on Windows in 0.33.1 and of the 204 of 381 package files that held a CR byte there (NFR-32).

## Changed

- Every text file the package writes now has LF line ends on every platform: the products, `products.json`, the post log and its JSON, the run records, the plans, the logs, the emitted solver scripts and the files the solver reads, and the counter and clock programs the solver runs. 0.33.1 wrote CRLF on Windows where a text mode stated no line end (NFR-32).
- The products snapshot judges line ends: the post runs with text mode forced to write CRLF, and its receipt names its platform and counts the files holding a CR (NFR-32).
- `scripts/check_parity.py` compares the post of 0.33.1 with CR before LF removed, lists those files under NFR-32, reports `post.cr_normalised` and `post.cr_in_release`, and fails on a CR in a release product (NFR-32).

## Migration

- **Every text file the package writes has LF line ends on every platform (NFR-32).** Up to 0.33.1 a file written on Windows ended its lines with CRLF where the writer stated no line end, and with LF on Linux; from 0.34.0 it is LF on both, in the products, records, logs and emitted solver scripts alike, and the only difference from 0.33.1 is the CR bytes removed before LF, except that the embedded counter and clock solver programs now state the LF line end in their own text, so their text and recorded sha256 change as well. There is no switch that restores CRLF. A reader that split lines on CRLF now reads LF: split with `str.splitlines()` or open the file in text mode, and a byte-exact comparison against a 0.33.1 file on Windows removes CR before LF first. A digest of a file written by 0.33.1 on Windows differs from the digest of the same file written by 0.34.0 for that reason alone (NFR-32).
