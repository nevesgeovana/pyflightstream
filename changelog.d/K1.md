## Added

- **The requirements of the post and its products for 0.25.0 to 0.28.0 are written.** The time-averaged surface (FR-112), the surface flow in VTK and CSV and the Tecplot file written from it (FR-113), the boundary-layer parameters (FR-115), one sectional-loads file and Cp file per distribution with the integrated loads (FR-116), the probes of an unsteady row as fluid plots (FR-117), the clock columns `J_CLOCK` and `RPM_CLOCK` (FR-118), a post that refuses nothing by default (FR-119), the post log in text and JSON (FR-120), and the polar as the first column of every table with no quoted cell (FR-124) each have a requirement in `docs/srs/functional-requirements.md`, with the need, the verifiable statement, the release that solved it and the test that proves it.
- **The requirements of the setup, the inputs and the geometry for 0.25.0 to 0.28.0 are written.** The setup key of every advanced setting (FR-114), the glossary and the template of the input files (FR-123), the custom free stream by an input file (FR-125), the surface names of a raw OBJ read from its groups (FR-126), the FSI blade properties from its sections and a material (FR-127), the actuator disc turned by the advance ratio (FR-128), and the refusal of `COLD_START` on an unsteady row (FR-134).
- **The requirements of the run for 0.25.0 to 0.28.0 are written.** The final saved simulation of every point (FR-121), the boundary names in the run record (FR-122), the readable local log with its progress (FR-129), the run that submits and does not post (FR-130), `--force-rerun-all` (FR-131), the plan warning for a plot group that takes the rotor table's name (FR-132), and the solver plots of an unsteady row (FR-133).
- **`scripts/assemble_srs.py` folds the requirement fragments of `docs/srs/fr.d/` into the functional requirements** under the heading `## 0.25.0 to 0.32.0 additions` and deletes them, the way `scripts/assemble_changelog.py` folds the change log. It is idempotent, and refuses a fragment with a heading of its own, a fragment with no requirement, an id written twice, and an id already in the page with another text. It carries FR-112 to FR-134 into the page when the release integrates.

## Changed

- **Every capability bullet of the change log of 0.25.0 to 0.28.0 now ends with the id of the requirement that states it**, or with `(no requirement: <reason>)` where the bullet is a recount, an example, a documentation change or an internal split (FR-112 to FR-134 are the new ones; the older ones are cited by their own ids). A test, `tests/tier1_offline/test_p0320_k1_srs_coverage.py`, fails when a bullet has neither and when a cited id does not exist. No other word of those releases changed.
