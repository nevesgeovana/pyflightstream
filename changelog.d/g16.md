`geometry iges-grid` reads the layout sidecar `<piece>.layout.json` that a generated wing carries beside its IGES (PFS-2214, G16). Each named face is cut along its base's iso lines (exact, the geometry file is never changed) before the four-sided test, so every layout block is meshed transfinite, and with `trailing_edge = "auto"` the trailing edge is the rim of the face with the `trailing_edge` role instead of the angle search. A sidecar that cannot be read, or that does not match the file (faces, component or area), is warned and the file is gridded as a foreign one; an IGES with no sidecar is gridded exactly as before. The record gains `layout` (the sidecars used, `null` when none) and `trailing_edges.<component>.source`. The sidecar reader `read_layout` returns the faces with their `u` and `v` lines in the shape the strategy 1 junction block classifier reads. A face with more than four curves is a block when exactly four of its points are corners (a skin edge the one-face tip cap cuts in two): the cells of a composite side are shared over its curves by length and the patch is given its corner points. The default join tolerance is taken from the faces' own extent, so a stray curve of an imported collapsed edge cannot inflate it.
