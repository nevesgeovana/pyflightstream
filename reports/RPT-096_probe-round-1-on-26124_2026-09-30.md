# RPT-096 - pyflightstream 0.32 probe round 1 on FlightStream 26.124 (2026-09-30)

The report of the first licensed probe round of pyflightstream 0.32.0
(GOAL-037): thirteen small scripts, each moving one thing, run one after the
other on **FlightStream 26.124, build 8172026**, executable SHA-256
`68e64e666fad6e403a6c6747b20c263f5c9f3e4c7542eebe253397bedcc30c65` (measured
by the runner before anything started; `exe_sha256_measured` in
`verdicts.json`). The package is the tree at `7adcabb8` (`package_commit`).
The round ran hidden, one solver instance at a time, from 01:10:49 to 01:11:09
UTC on 2026-09-30, and every script sets far field 5 layers. Nothing here
changes the command database: promotion goes only through a `qa.specs` catalog
entry and `pyfs-qa probe`.

Only nondimensional values are stated. The geometry of the CCS probes is a set
of generic shapes built from public shape laws, the mesh probes use the
library's tier-3 meshes, and the round states no length, speed, rotor speed or
time step of any of them; the scripts hold the values and stay in the round's
folder.

## 1. How a verdict is read

Every probed command is followed by a step sentinel (`PRINT PYFS_R1_<id>_Snn_<COMMAND>`)
and its own `EXPORT_LOG`. The runner reads, in this order: **removed** (the
solver's log carries `Unrecognized command` for it), **broken** (its sentinel
never printed and the script stopped at it, or it ran and a judged check
failed), **verified** (its sentinel printed and the judged check held),
**unprobed** (it was accepted and no instrument observes an effect). The
instrument for geometry is the package's own boundary reader on a `SAVEAS`
(RPT-039, RPT-022) and the face count of an OBJ export.

Totals over the round: **14 commands verified, 26 accepted and unprobed, 1
broken**. No command was reported as unrecognised.

## 3. What each group read

### 3.1 The CCS lofts and the refused control surface

`CCS_IMPORT` brings in all three components of the generic CCS file, and each
script route builds its component from the same file with the same face count
as the import for the wing (4484) and the body of revolution (4661); the
fuselage differs (3871 against 3792), so its two routes are not the same mesh
and the round does not say why. The three accepted preparation commands
(`CAD_CREATE_INITIALIZE`, `CAD_CREATE_IMPORT_CURVE_CCS`, `CAD_CREATE_CURVE_SELECT`)
have no instrument of their own and read **unprobed**, though every loft that
follows them worked.

`CCS_WING_MESH_SUBDIVISIONS CHORD 30` is accepted and changes the wing from
4484 faces to 588, the only difference between C1 and C2.

`NEW_CCS_WING_CONTROL_SURFACE` with the seven values above is **refused on its
arguments**: the solver's crash log holds `ERROR | Scripting | N/A | Error in
script ... at line 24: 'NEW_CCS_WING_CONTROL_SURFACE PYFS_AIL 0.5 0.9 0.25 0.25 0.5 20.0 1.0'
| Review command syntax and arguments.` The command is not reported as
unrecognised, so it exists in 26.124; the script stopped at it, the sentinel
after it never printed, and neither the saved state nor the mesh export was
written. Which argument the solver refused is not read.

### 3.2 The direction digit (G35)

Both files import, into the same single fuselage. The two saved states differ
in 5 lines. That is all that was read: the lines were not decoded and no
geometry was compared, so the round shows the digit is **accepted**, and shows
the saved state is not identical, but **does not observe its effect**.

### 3.3 DELETE_SURFACES

Inventory read from the saved simulation with the package's boundary reader:
before `Body, Base, Blade1, Blade2`; after `DELETE_SURFACES 3` it is `Body,
Base, Blade2`. Blade2 moved from index 4 to index 3, the renumbering an
inventory must follow, and the OBJ export of index 3 after holds only Blade2
(1040 faces), a second reading of which surface index 3 became.

### 3.4 Wake stabilization DISABLE

The three saves differ pairwise: default against ENABLE by 2 lines, ENABLE
against DISABLE by 1 line, and default against DISABLE. So DISABLE is stored
(it changed the state that ENABLE left) and it does not bring the state back to
the default's bytes. The differing lines were not decoded.

### 3.5 The acoustic chain and the sources-off control

A0 and A1 differ in the `ACOUSTIC_SOURCES` token only, and both ran the chain
to its last command with no log error. The exported `signals.txt` of each holds
3 observers (`PYFS_OBS1` created, two imported from the file), 16 rows each:

| run | PL | PT | PO |
|---|---|---|---|
| A0, sources DISABLE | 0.0 in every row of the 3 observers | 0.0 | 0.0 |
| A1, sources ENABLE | nonzero; largest absolute values 0.38, 0.41 and 0.24 (one per observer) | 0.0 | equal to PL |

So the flag is read by the solver and changes what the chain exports, and the
sources-off control is exactly zero, the natural check that the nonzero
values of A1 are the sources'. Four commands read **verified** by this
comparison: `ACOUSTIC_SOURCES`, `CREATE_NEW_ACOUSTIC_OBSERVER` (its name is in
the export), `EXPORT_ACOUSTIC_SIGNALS` and `CREATE_ACOUSTIC_SECTION` (16 VTK
files written into its folder in each run). `ACOUSTIC_OBSERVERS_IMPORT` (the
log names the file it read, and the two imported observers are in the export),
`SET_ACOUSTIC_OBSERVER_TIME` and `COMPUTE_ACOUSTIC_SIGNALS` were accepted and
read **unprobed** by the runner's rules.

## What this round does not establish

- **The effect of the G35 direction digit.** Only that the saved states differ (section 3.2).
- **The observer time window's relation to the solver time.** `SET_ACOUSTIC_OBSERVER_TIME 0.05 0.2 16` was chosen by the script for a march of 24 steps; the export's 16 time rows run from the window's start to just under its end (0.19 of the 0.2), and nothing read ties an observer row to a solver step or shows that the window lies inside the solved span.
- **Which argument of `NEW_CCS_WING_CONTROL_SURFACE` was refused**, or whether any argument set is accepted.
- **Why the fuselage routes differ** in face count (section 3.1).
- **The content and the count of the section's 16 VTK files**: the script asked for a section of 2 radial by 4 azimuth observers, and 16 files were written in each run; whether that is one file per observer time step, and what each file holds, is not read.
- **Why PT is exactly zero** with the sources on, and whether PO equalling PL is the solver's definition or a property of this scaffold.
- **An acoustic chain on a solved propeller run.** The scaffold is a library mesh in a short march, so amplitudes say nothing about a real case.
- **What the differing lines of the G35 and wake stabilization saves are.**
- **Any command the runner read as unprobed** (26 of 41): they were accepted and no instrument observed their effect.
