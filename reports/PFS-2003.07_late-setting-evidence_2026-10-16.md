# PFS-2003.07: late minimum-Cp response

Date: 2026-10-16. Offline review of licensed batch-3 evidence.

The measured command is SOLVER_MINIMUM_CP, not SOLVER_SET_FARFIELD_LAYERS.
Both 26.124 build 8172026 and 26.125 build 10052026 distinguish an early -20
control from an early 0 control. Default equals early -20, and setting 0 after
INITIALIZE_SOLVER but before START_SOLVER equals early 0 for every exported
coefficient. CL changes by -4.1773699 and -4.1399165 respectively, far above
the printed step 0.0000001. This disproves an initialization-only reading
for this setting on these builds. Other advanced settings are not covered.

The scripts import the same meter geometry and trailing-edge file, set five
far-field layers, disable Kutta-Joukowski lift forces, initialize an
incompressible solver without symmetry, and run at 8 degrees and 30 m/s.
The ceiling is 300 iterations and requested convergence is 1e-10. All arms
reach the ceiling; the logged velocity/pressure residuals are
8.2227804e-7/5.3473963e-7. Numerical response is measured. Convergence adequacy
and physical interpretation remain session judgments; this report closes
neither and does not promote a command status.

The builder's init phase already permits the measured late-before-start
placement. The offline test
`test_script.py::test_p0420_p2_1a_minimum_cp_can_follow_initialization`
passes before this documentation change and is a preservation control,
not a claimed red-to-green code repair. Workflows retain safe early placement.
